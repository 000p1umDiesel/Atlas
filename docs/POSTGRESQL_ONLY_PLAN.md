# PostgreSQL как единственный SQL backend

Пользователь одобрил полный отказ от рабочего SQLite backend и очистку текущих данных для повторной загрузки. Исходные документы, настройки, секреты, код и веса моделей сохраняются.

## Решение

PostgreSQL хранит registry, очередь заданий, загрузки, пользователей, команды, сессии и чаты. Qdrant хранит векторы, Neo4j — граф и аналитику APOC/GDS. SQLite используется только командой импорта старых файлов; работа приложения с SQLite и автоматическое переключение запрещены.

Существующие PostgreSQL namespaces, блокировки advisory lock, атомарность очереди, порядок извлечений и изоляция команд сохраняются. Маркер проекта остаётся локальным. Изменения Leiden из предыдущей задачи сохраняются.

## Задачи

1. Добавить проверки отказа от `database.backend: sqlite` и файловых SQL targets. Удалить соединения SQLite, ветвления и SQLite SQL из рабочего кода.
2. Перевести хранилища и тесты на PostgreSQL, сохранив проверки гонок, отката транзакций, изоляции и порядка записей. Тесты, требующие SQL сервера, явно используют изолированный PostgreSQL.
3. Сохранить `database migrate-sqlite` и проверить импорт исторических SQLite fixtures в PostgreSQL, неизменность источников и атомарный отказ при ошибках.
4. Обновить README; выполнить unit, integration, API E2E, Ruff, форматирование и проверку diff. Провести независимое ревью.
5. Очистить данные настроенного проекта и команд в PostgreSQL, Qdrant и Neo4j, сгенерированную wiki, кэши, SQLite-файлы и старые результаты/логи. Проверить пустое состояние. Не удалять исходные документы, тестовые fixtures, конфигурацию, секреты, код и веса.

## Критерии готовности

- Конфигурация SQLite и передача пути вместо PostgreSQL target завершаются понятной ошибкой.
- Приложение и тесты рабочего поведения используют PostgreSQL; SQLite встречается только в миграторе и его fixtures/проверках.
- Очередь выдерживает конкурентные операции, не теряет незавершённые записи и откатывает частичные ошибки.
- Генерация через настроенный API подтверждена; локальная LLM не запускается.
- Данные проекта пусты после проверок, документы доступны для повторного ingest.
