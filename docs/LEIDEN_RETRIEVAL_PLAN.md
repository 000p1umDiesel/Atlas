# Leiden в контексте ответа

**Цель:** использовать уже рассчитанные сообщества Leiden в `graph` и `all`, чтобы LLM
получала дополнительные исходные фрагменты с проверяемыми ссылками.

**Подход:** графовый поиск находит стартовые сущности, обычный обход собирает локальные
связи, затем актуальная аналитика выбирает сообщества стартовых сущностей. Ограниченный
набор участников по PageRank ведёт через `MENTIONS` к исходным чанкам. Их текст получает
обычный `Answerer`; идентификаторы сообществ сами по себе не служат фактическими источниками.

Обзоры сообществ с отдельными LLM-вызовами рассмотрены как следующий самостоятельный этап:
они требуют хранения текста, обновления при изменении документов и проверки цитат.
Здесь выбран подбор исходных фрагментов: он использует существующую модель данных и
не добавляет LLM-вызовов к одному ответу.

## Ограничения и интерфейсы

- `graph.use_gds` и `graph.community.enabled` включают расширение совместно.
- Библиотечные defaults выключены; в проектном `config.yaml` расширение включено.
- `GraphCommunitySettings`: `enabled=False`, `max_communities=3`, `max_entities=30`
  (на сообщество), `max_chunks=3`, `timeout_s=5`.
- `GraphStore.community_chunks(seed_ids, limit, *, max_communities, max_entities,
  exclude_chunk_ids, timeout) -> list[ChunkView]` выполняет один ограниченный запрос.
- Состояние, сущности, чанки и документы обязаны иметь labels текущей команды.
- Только `AnalysisState.run_id` и совпадающий `Entity.analytics_run_id` разрешают чтение.
- Неактуальный/отсутствующий анализ даёт прежний поиск. Таймаут расширения также даёт
  обычный контекст; ошибки подключения/авторизации не скрываются.
- При наличии локальных подтверждений не более половины `k` отдаётся расширению;
  оставшиеся места заполняются локальными. Всего уникальных исходных чанков не больше `k`.
- Подтверждения связей и их порядок сохраняются. Дополнительные чанки исключают уже
  выбранные подтверждения; при маленьком контекстном бюджете источники идут перед
  описаниями сущностей и связей, когда расширение реально добавило контекст.

## Review Focus

- Совпадающие entity/chunk IDs и community keys разных команд не смешиваются.
- Новый ingest/удаление/clear запрещает чтение прежних memberships.
- Большое сообщество, пустые seeds, `k=0/1`, совпадающие чанки не ломают лимиты.
- Leiden не вытесняет все непосредственные подтверждения вопроса.
- Реальный API получает дополнительный текст и возвращает цитату к исходному чанку.
