## Что именно доказывает проверка API

Использовано существующее подключение из `config.yaml`/`.env`: `serve: api`,
`gpt-6-luna`, `https://codex.sale/v1`, переменная `LLM_API_KEY`.
Это сторонний OpenAI-совместимый API. Ключ не менялся и не выводился.
Эмбеддер и реранкер использованы настроенные, уже работающие; локальный LLM не запускался.

В `tests/e2e/test_leiden_e2e.py` реальный GDS рассчитывает Leiden и PageRank на
контрольном графе, реальный APOC выполняет обход глубины 1. При выключенном расширении
доступен только `proof:00000`; там нет контрольного факта. При включённом расширении
добавляются `proof:00001` и `proof:00002`. Только `proof:00001` содержит код `ORCHID-734`.
API возвращает этот код и цитату к `proof:00001`, сохраняя путь
`/fixtures/community-proof.md` и страницу 2. Оба сценария `graph` и графовой части `all`
прошли. Вызов answer получает 401 входной токен; ответы заняли 22 и 18 выходных токенов.
Этот сценарий `all` специально проверяет графовый компонент через `CombinedRetriever`;
он сам по себе не доказывает взаимодействие с конкурирующими RAG/wiki результатами.

Отдельный полный E2E использует `build_retrievers` со всеми компонентами: реальные
RU/EN Markdown, DOCX, PDF → парсинг → embedding → API extraction/resolution → Neo4j →
API wiki → GDS analysis → ответы в `rag/wiki/graph/all` с цитатами → повторный ingest.
Командные HTTP/CLI E2E проверяют очередь, ответы и чат, авторизацию, удаление и
изоляцию на SQLite и PostgreSQL. Также прошли все 24 live-проверки prompt injection.
Первый общий запуск: `29 passed, 701 deselected, 1 error in 544.02s`; ошибка была в
teardown нового теста, который вызвал `wipe()` после `app.aclose()` и закрытия драйвера.
После исправления повторный полный flow прошёл без ошибок: `1 passed in 153.80s`.
Все 29 уникальных E2E-сценариев проверены; это результаты двух запусков, не одного.
Повторный полный flow: 4 документа, 20 сущностей, 25 связей, 3 сообщества;
повторный ingest пропустил все 4 документа. API потратил в этом запуске 31 693 входных
и 5822 выходных токена (включая extraction/resolution/wiki/answers).

## Границы проверки

- Подтверждена работоспособность расширения и передача дополнительных источников LLM.
  Универсальное улучшение качества ответов не измерялось на репрезентативном наборе вопросов.
- Review отметил дополнительные возможные проверки: насыщенный локальными источниками
  лимит `k`, тесный токенный бюджет, несколько упоминаний одного чанка и большой fanout.
  Текущие тесты проверяют малые графы; это не нагрузочный benchmark.
- Ограничиваются выбранные сообщества/участники и возвращаемые чанки. Число упоминаний
  выбранных сущностей зависит от корпуса; запрос имеет таймаут, который возвращает
  обычный контекст при превышении. Оценка памяти GDS не является жёстким RSS-лимитом.
- Генерируемые обзоры сообществ и глобальный поиск по обзорам не реализуются этим изменением.

## Исправление, найденное полной проверкой

Повторный unit-набор выявил исходную гонку
`test_concurrent_first_queue_open_migrates_once`: SQLite возвращал `SQLITE_BUSY` при
`PRAGMA journal_mode=WAL` параллельных первых подключений. Для этой ошибки обычный
busy timeout может не вызываться (см. [SQLite busy handler](https://www.sqlite.org/c3ref/busy_handler.html)).
Добавлен ограниченный повтор только BUSY/LOCKED и закрытие соединения при ошибке
инициализации. Невосстановимые ошибки не скрываются. PostgreSQL не менялся.
Два детерминированных регрессионных теста сначала упали, затем прошли; тесты очереди
и весь unit-набор после исправления зелёные. Это отдельная малая правка, обнаруженная
при запрошенной полной проверке, после статического review Leiden.

PostgreSQL и Qdrant также пересозданы штатной Compose-командой: прежний `json-file`
заменён на настроенный `local` с buffer 1m и ротацией 10m × 3; общий RAM+swap равен
лимиту RAM (1 GiB и 2 GiB). Состояние CLI `status` до и после совпало побайтно.

После завершения `docker ps` содержит только три рабочие базы проекта; тестовые
контейнеры остановлены. Изначально работающие серверы моделей сохранены.
README и новые Markdown-ссылки проверены; итоговые Ruff/format/diff проверки прошли.
