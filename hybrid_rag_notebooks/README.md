# Hybrid RAG: от PDF до проверяемого ответа

Три самостоятельных ноутбука разбирают **Attention Is All You Need**. Они рассчитаны на человека, который знает Python и изучает RAG. Основной алгоритм виден в ячейках: вызовы Docling, чанкера, Qdrant, генератора и Ragas сопровождаются просмотром данных.

| Ноутбук | Что выполняем | Что проверяем |
|---|---|---|
| [01 — Документы и индекс](01_hybrid_rag.ipynb) | Docling + Xiaomi VLM → HybridChunker → dense + BM25 → Qdrant | Исходная страница, таблицы, описания картинок, границы и длины чанков, векторы и payload |
| [02 — Поиск и inference](02_hybrid_rag_inference.ipynb) | Dense / BM25 → RRF → reranker → соседи → контекст → LLM | Позиции до и после объединения, полный промпт, ответ и ссылки |
| [03 — Ragas](03_hybrid_rag_ragas.ipynb) | Сохранённые ответы → один вызов метрики → пакетная оценка | Управляемая ошибка в ответе, пять метрик, пропуски, слабые ответы, сравнение запусков |

Каждый этап следует порядку: **объяснение → код → результат → проверка**. Сначала пройдите один вопрос; эксперименты и пакетные этапы идут после основного примера. Markdown можно читать без kernel, реальные выводы появляются при выполнении ячеек.

## Запуск

Следуйте [SETUP.md](SETUP.md): Python 3.12 → зависимости → `.env` → сервисы → ноутбуки по порядку. Папку можно скопировать отдельно: пакет `mnogobase`, Neo4j и wiki не нужны.

- **01:** нужны Qdrant, embeddings и Xiaomi VLM; первый запуск Docling/OCR и BM25 может скачивать модели. Лимит основного индекса — 512 токенов; сравнение с 256 не меняет индекс. Генератор и судья не вызываются.
- **02:** нужны Qdrant, embeddings, reranker и генератор. Сначала одиночный ответ, затем сравнения и пакет всего набора. Перевод запроса выключен; его можно включить в отдельном эксперименте.
- **03:** нужны судья и embeddings судьи. Поиск и inference не повторяются. Сначала одиночная Faithfulness и искажённый ответ, затем пять метрик для трёх вопросов. `LIMIT=None` включает весь набор.

**Мультимодальность включена по умолчанию (`vision=True`).** В основном маршруте 01 Docling извлекает текст и таблицы, а **`prithivMLmods/Xiaomi-OCR-0-GGUF:Q6_K`** описывает картинки, графики и схемы. Описания добавляются до сохранения Docling JSON и чанкирования; ошибка VLM не позволяет закэшировать неполный документ. В 02 эти описания уже участвуют в поиске, поэтому повторно вызывать VLM для вопроса не нужно. Настройки находятся в `helpers/settings.py` и `.env`; команда VLM включает `--image-min-tokens 1024` для небольших картинок из PDF. Для явного отключения задайте `CFG['vision'] = False` в 01 до подключения и выберите другие имена индекса и коллекции.

**Run All выполняет модельные вызовы и записывает результаты.** Ноутбуки используют отдельные kernels: обмен идёт через файлы и Qdrant. В 01 и 02 задайте одинаковый `INDEX_NAME`, в 02 и 03 — одинаковый `RUN_NAME`. Мультимодальный маршрут использует индекс `attention_multimodal_v1`, коллекцию `notebook_attention_multimodal_v1`, запуск `attention_multimodal_hybrid_v1` и оценку `ragas_multimodal_v1`. Прежние текстовые индексы и результаты не перезаписываются; для нового маршрута выполните ноутбуки по порядку.

## Что должно стать понятно

1. Чем извлечение PDF отличается от чанкирования; как `HybridChunker`, токенизатор и заголовки влияют на фрагменты.
2. Чем Dense отличается от BM25; как RRF объединяет позиции и что меняет reranker.
3. Как выбранные чанки становятся точным контекстом, а контекст и вопрос — входом генератора.
4. Почему хорошая Faithfulness не гарантирует полноту ответа; какие метрики требуют эталон и как разбирать отказ.

Полезные проверки по статье: не перепутаны ли base и big, сохранились ли числа и условия таблицы, подтверждаются ли ссылки ответом? Для вопроса о seed ожидается признание отсутствия данных. В третьем ноутбуке сравнивайте запуски на одинаковых вопросах с одинаковым судьёй; средние считаются по общим успешным парам.

## Код и сохранение результатов

В `helpers` остаются HTTP-клиенты, настройки, checkpoints, описание картинок и вывод отчётов. Основные шаги нового маршрута реализованы в ноутбуках: преобразование Docling, добавление описаний, чанкирование и индексация видны в ячейках. `add_image_descriptions` используется и в 01, и в `DocumentParser`. Прежние `RAGLab`, `HybridRetriever`, `EvaluationLab` и их проверки сохранены для совместимости; вызывать их для прохождения новых ноутбуков не требуется.

Структура `index.json`, `binding.json`, `parsed/`, `run.json`, `answers.jsonl` и `evaluations/` сохранена. Добавлен `docling/` с промежуточными структурированными документами. После прерывания повторите ячейку: успешные элементы используются повторно. После перезапуска kernel выполняйте сверху вниз.

Для другого корпуса/чанкирования/embeddings выберите новые имена индекса и коллекции; для другого поиска или промпта — новое имя запуска; для другого судьи — новое имя оценки. Изменение конфигурации под старым именем вызывает ошибку. Не запускайте два писателя одного каталога одновременно.

Оценка перенесена из прежнего `02_hybrid_rag_ragas.ipynb` в **`03_hybrid_rag_ragas.ipynb`**. Сохранённые старые ответы доступны через их `RUN_NAME`.

Проверки без реальных моделей из этой папки:

```bash
python -m unittest discover -s tests -v
```

Проверки выполняют ячейки трёх ноутбуков на подставных API и Qdrant в памяти, включая сохранение, восстановление и оценку. Реальный PDF/OCR, качество моделей и установка зависимостей с нуля проверяются отдельно.

Для Xiaomi-OCR-0 Q6_K дополнительно выполнены реальные ячейки разбора и чанкирования ноутбука 01 на двух PNG, DOCX и PDF: шесть запросов к VLM, описания в чанках, повтор из кэша без новых запросов. Описание схемы со второй страницы контрольного PDF сохранило нужный раздел и страницу. Использован сервер проекта на порту 8003 с `--image-min-tokens 1024`; токенизатор VLM использован для этой изолированной проверки разбора. Полный запуск индексации, генератора и Ragas с реальными сервисами здесь не выполнялся. Ошибки перевода и интерпретации графиков у модели остаются возможными.
