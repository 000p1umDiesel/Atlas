# Подключение и воспроизведение

[К обзору](README.md) · [Первый ноутбук](01_hybrid_rag.ipynb) · [Поиск и inference](02_hybrid_rag_inference.ipynb) · [Оценка](03_hybrid_rag_ragas.ipynb)

## Маршрут первого запуска

1. Создайте Python-окружение и скопируйте `.env.example` в `.env` (команды ниже).
2. Заполните настройки генератора. Проверьте адреса и имена локальных моделей.
3. Запустите Qdrant, embeddings и reranker. Для базового примера VLM не требуется.
4. Откройте ноутбук 01, выполните настройки и печать команды embeddings. Ноутбук 02 дополнительно печатает команды reranker. Команды нужно выполнить в отдельных терминалах; сама ячейка ничего не запускает.
5. В 01 проверьте соединения, разберите PDF и постройте индекс. Откройте 02 с тем же INDEX_NAME и получите один ответ.
6. В ноутбуке 02 выполните пакетную ячейку, затем откройте ноутбук 03 с тем же `RUN_NAME`. Начните с трёх вопросов.

Установка Python-пакетов не устанавливает `llama-server` и не запускает модели.
Первый раз Docling, BM25 и llama.cpp могут скачивать веса; последующие запуски используют кэш.

## Что к чему подключается

| Компонент | Зачем | Настройки в `.env` | Когда нужен |
|---|---|---|---|
| Qdrant | Хранит фрагменты, dense-векторы и BM25-веса | `QDRANT_URL` | Индексирование и поиск |
| Embeddings | Превращает текст в векторы; сервер также предоставляет токенизатор | `EMBED_BASE_URL`, `EMBED_MODEL`, `EMBED_API_KEY` | Базовый маршрут, в том числе разбор с серверным токенизатором |
| Reranker | Переставляет найденные фрагменты по соответствию вопросу | `RERANK_BASE_URL`, `RERANK_MODEL`, `RERANK_API_KEY` | В 02 при `SEARCH['rerank']=True` |
| Генератор | Переводит запрос и пишет ответ по контексту | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | Ноутбук 02 |
| VLM | Добавляет текстовые описания изображений | `VISION_BASE_URL`, `VISION_MODEL`, `VISION_API_KEY` | В сохранённом расширенном маршруте DocumentParser |
| Судья | Проверяет сохранённые ответы | `JUDGE_BASE_URL`, `JUDGE_MODEL`, `JUDGE_API_KEY` | Расчёт Ragas |
| Embeddings судьи | Сравнивает вопросы для Answer Relevancy | `JUDGE_EMBED_BASE_URL`, `JUDGE_EMBED_MODEL`, `JUDGE_EMBED_API_KEY` | Answer Relevancy |

Генератор и судья — роли: их может выполнять одна модель. Пустые `JUDGE_*` наследуют настройки генератора; непустой `JUDGE_API_KEY` имеет приоритет над `LLM_API_KEY`, даже если судья обращается к тому же провайдеру; пустые `JUDGE_EMBED_*` — embeddings поиска. Судье нужна поддержка структурированного JSON-ответа. Для чтения учебного примера сервисы вообще не нужны.

Адрес API — куда отправлять запросы; имя модели — какой `id` выбрать на сервере; ключ — доступ к этому серверу. Их нельзя подставлять друг вместо друга.

После копирования `.env.example` замените как минимум эти строки (значения ниже — плейсхолдеры):

```dotenv
LLM_BASE_URL=https://your-provider.example/v1
LLM_MODEL=your-model-id
LLM_API_KEY=your-api-key
```

Остальные строки примера задают локальные порты: Qdrant 6333, embeddings 8101, reranker 8102, VLM 8103. Ключи локальных серверов без авторизации можно оставить пустыми. Не сохраняйте настоящие ключи в ноутбуках или Git.
В базовом ноутбуке `vision=False`: текст и OCR остаются, но сведения, доступные только на изображении, могут потеряться.

## Окружение

Все команды ниже выполняйте **из этой папки**. Установку и запуск выполняете вы.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name hybrid-rag --display-name 'Python (hybrid-rag)'
cp .env.example .env
python -m jupyter lab
```

Windows PowerShell: вместо `source` используйте `.venv\Scripts\Activate.ps1`, вместо `cp` можно использовать `Copy-Item`. Выберите kernel **Python (hybrid-rag)**. У ноутбуков расширение `.ipynb`.

`requirements.txt` закрепляет версии основных зависимостей по доступному окружению разработки; установка в чистом окружении здесь не выполнялась. GPU не нужен для Python-кода: Docling и FastEmbed по умолчанию работают на CPU. Серверы Qwen могут использовать GPU/Metal. Вариант `device='mps'` применим к Docling на macOS, `cuda` — к настроенному CUDA-окружению. Requirements рассчитан на обычный CPU ONNX Runtime; настройка GPU для OCR/FastEmbed — отдельная задача.

## Серверы

В ноутбуках 01 и 02 обычные ячейки печатают команды необходимых им моделей из текущего `CFG`. Ноутбук создаёт HTTP-клиенты к уже запущенным серверам: `ModelAPI(...)` не скачивает веса и не запускает процессы. Установка Python-зависимостей также не устанавливает `llama-server`.

Если серверы проекта уже работают, используйте их адреса. Самостоятельный вариант:

```bash
docker run -d --name notebook-rag-qdrant -p 6333:6333 -v notebook_rag_qdrant:/qdrant/storage qdrant/qdrant:v1.19.2
```

Если порт 6333 занят существующим Qdrant, второй контейнер не нужен. Ноутбук создаёт отдельную коллекцию `notebook_attention_steps_v1`.

Для ноутбуков по умолчанию выбраны отдельные порты: **embeddings 8101, reranker 8102, VLM 8103**. Любой из них можно поменять в `hybrid_rag_notebooks/.env` через `EMBED_BASE_URL`, `RERANK_BASE_URL`, `VISION_BASE_URL`. Команды формируются из текущего `CFG`, включая порты и имена моделей. Выполните настройки и ячейку печати команд, затем скопируйте их в отдельные терминалы. У работающего сервера порт изменится после перезапуска с новым `--port`.

Установите `llama-server` из llama.cpp самостоятельно (на macOS: `brew install llama.cpp`). Запускайте каждую команду в отдельном терминале; `--alias` должен совпадать с именем модели в `.env`:

```bash
llama-server -hf mradermacher/Qwen3-Embedding-0.6B-GGUF:Q8_0 --alias mradermacher/Qwen3-Embedding-0.6B-GGUF:Q8_0 --embedding --pooling last --host 127.0.0.1 --port 8101 --ctx-size 8192 --batch-size 8192 --ubatch-size 8192 --parallel 1 --n-gpu-layers 999
```

```bash
llama-server -hf gorse-io/Qwen3-Reranker-0.6B-GGUF:Q8_0 --alias gorse-io/Qwen3-Reranker-0.6B-GGUF:Q8_0 --embedding --rerank --pooling rank --host 127.0.0.1 --port 8102 --ctx-size 8192 --batch-size 8192 --ubatch-size 8192 --parallel 1 --n-gpu-layers 999
```

```bash
llama-server -hf unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_K_M --alias unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_K_M --host 127.0.0.1 --port 8103 --ctx-size 8192 --parallel 1 --n-gpu-layers 999
```

Для VLM нужен multimodal GGUF и проектор из того же репозитория; текущий llama.cpp загружает его через `-hf`. Если ваша сборка этого не делает, загрузите соответствующий проектор и задайте `--mmproj /path/to/mmproj.gguf`. Для CPU замените `--n-gpu-layers 999` на `--n-gpu-layers 0`; для VLM добавьте `--no-mmproj-offload`. Если не хватает памяти, уменьшите число GPU-слоёв или отключите VLM в `CFG`. `CFG['device']` управляет Docling, а устройство моделей выбирают флаги `llama-server`.

При первом старте `-hf` скачивает GGUF с Hugging Face; прогресс загрузки и ошибки видны в соответствующем терминале. Повторный запуск использует локальный кэш. Дождитесь готовности каждой используемой модели:

```bash
curl --fail --show-error http://localhost:8101/health
curl --fail --show-error http://localhost:8102/health
# Только если включили VLM:
curl --fail --show-error http://localhost:8103/health
```

Готовый сервер отвечает HTTP 200 и `{"status":"ok"}`. HTTP 503 означает, что модель ещё загружается; `Connection refused` — что на этом адресе никто не слушает. VLM можно не запускать при `CFG['vision'] = False`, reranker — при `CFG['rerank'] = False`. Embeddings нужны и для индекса, и для токенизатора. Остановка каждой модели — `Ctrl+C` в её терминале; Qdrant — `docker stop notebook-rag-qdrant`, повторный запуск — `docker start notebook-rag-qdrant`.

Имена и адреса LLM, embeddings, reranker, VLM и судьи можно переопределить в `.env`. Для генератора по умолчанию используется адрес из конфигурации проекта. Заполните `LLM_API_KEY`; ключи не нужно писать в ячейках. Судья должен поддерживать структурированный JSON-ответ. Переменные `JUDGE_*` позволяют задать другого судью; пустые значения наследуют настройки генератора/embeddings.

`RAGAS_DO_NOT_TRACK=true` отключает отправку статистики использования разработчикам Ragas. На метрики это не влияет: запросы к выбранному судье и embeddings продолжают выполняться. `prepare_environment()` задаёт это значение по умолчанию до загрузки Ragas, сохраняя явно заданное значение из окружения или `.env`. См. [описание аналитики Ragas](https://github.com/vibrantlabsai/ragas#-open-analytics).

`JUDGE_EMBED_*` — embeddings только для Answer Relevancy. Судья составляет вопросы по проверяемому ответу, а embeddings позволяют сравнить их по смыслу с исходным вопросом. При пустых `JUDGE_EMBED_BASE_URL`, `JUDGE_EMBED_MODEL` и `JUDGE_EMBED_API_KEY` используются соответствующие `EMBED_*`, поэтому можно обойтись уже работающим сервером поиска. См. [описание Answer Relevancy](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/answer_relevance/).

Если используете уже работающие серверы проекта, сверьте `EMBED_MODEL`, `RERANK_MODEL`, `VISION_MODEL` с `id` из `GET <BASE_URL>/models`: модели проекта могут отличаться от небольших моделей в примерах ноутбука. После изменения `.env` перезапустите kernel и выполните ячейки сверху вниз: уже созданные клиенты сохраняют прежние настройки, а переменные окружения процесса имеют приоритет над `.env`.

Флаги запуска, `/health` и автоматический выбор проектора описаны в [документации llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md); настройка Qwen reranker — в [карточке модели](https://huggingface.co/gorse-io/Qwen3-Reranker-0.6B-GGUF#run-with-llamacpp).

Ноутбук рассчитан на endpoints `/v1/embeddings`, `/v1/rerank`, `/v1/chat/completions`. Для GGUF токенизатор берётся через `/tokenize` сервера embeddings. Для vLLM задайте исходный HF-репозиторий модели в `CFG['tokenizer_hf']`. Не указывайте GGUF-репозиторий как HF-токенизатор.

Новый маршрут без VLM использует `INDEX_NAME="attention_steps_v1"`, `COLLECTION="notebook_attention_steps_v1"`, `RUN_NAME="attention_steps_hybrid_v1"`. Прежние `attention_text_v1` и `attention_v1` остаются отдельными экспериментами. Для оценки их ответов задайте соответствующий `RUN_NAME` в 03.

## Документы и первый запуск

Выполняйте ячейки сверху вниз: в 01 — подключение, разбор, чанкирование и индекс; в 02 — загрузка индекса, поиск, генерация и пакетный inference; в 03 — оценка сохранённых ответов. Сейчас корпус — `data/documents/Attention is all you need.pdf`: статья [Attention Is All You Need, arXiv v7](https://arxiv.org/abs/1706.03762v7), 15 страниц. Для неё подготовлен набор вопросов ниже. В базовом ноутбуке `CFG['vision'] = False`. Новый пошаговый парсер отклоняет `True`: для описаний рисунков используйте сохранённый `helpers.parsing.DocumentParser` и отдельный индекс. PDF содержит текстовый слой, а вопросы о рисунках опираются на подписи; в основном маршруте достаточно `vision=False`, OCR остаётся включённым. Для другого корпуса смените `DOCUMENTS_DIR` и набор вопросов.

Основной новый маршрут показывает PDF и встроенные форматы DocumentConverter (например, Markdown). Для TXT, описания изображений через VLM и прежнего расширенного маршрута сохранён `helpers.parsing.DocumentParser`. Его поддерживаемые расширения: `pdf`, `docx`, `pptx`, `xlsx`, `html`, `htm`, `md`, `adoc`, `csv`, `txt`, `png`, `jpg`, `jpeg`, `tif`, `tiff`, `bmp`, `webp`. TXT читается как UTF-8; остальные форматы разбирает Docling. Для PDF и изображений включён OCR RU/EN. Изображения описываются VLM и добавляются в текстовый индекс. При отключении VLM текстовый поиск работает по OCR/извлечённому тексту. Битые, защищённые или пустые документы показываются как ошибки, без отметки об успешной загрузке.

Первый запуск Docling/OCR и `Qdrant/bm25` скачивает модели. Для закрытых HF-репозиториев понадобится `HF_TOKEN`. Парсинг PDF может идти долго: следите за журналом Docling и полосой прогресса по файлам. API-запросы ограничены таймаутом и повторяются при сетевых ошибках, HTTP 429 и 5xx.

В новом учебном маршруте перевод выключен; отдельная ячейка позволяет проверить его влияние. Далее: dense + BM25 и RRF; 30 кандидатов; reranker с ограничением 4000 символов на документ; top-8; до двух соседних чанков той же секции. Контекст ограничивается приблизительной оценкой `max(1, len(text) // 4)` на элемент, как в приложении; первый элемент сохраняется даже сверх бюджета. Проверяйте, что окно вашей LLM вмещает контекст и ответ. Оценки разных ветвей поиска не сравниваются напрямую.

Технические отличия от приложения: идентификатор документа учитывает путь и содержимое; нет registry/графа/wiki; описания картинок явно добавляются текстовыми узлами; все параметры задаются здесь. Для картинки без текстовой структуры описание может не иметь номера страницы. Обработка офиса/изображений зависит от возможностей Docling и доступности пикселей в документе — недоступное изображение даёт явную ошибку.

## Свои вопросы и оценка

В `data/questions.jsonl` подготовлено **40 вопросов к Attention Is All You Need**: 36 с эталонными ответами и 4 на отсутствие ответа или неверную предпосылку; 32 вопроса на русском и 8 на английском. Эталоны написаны на русском, как и ответы генератора по умолчанию. Первые три вопроса проверяют основной вклад статьи, объяснение scaled dot-product attention и различие параллельного обучения с авторегрессионной генерацией.

Набор охватывает архитектуру, Q/K/V, маски, multi-head attention, позиционные кодировки, сложность, обучение, декодирование, таблицы результатов, ablations, перенос на parsing и подписи к рисункам. Есть вопросы, для которых надо соединить факты из разных разделов. Пример минимальной строки:

```json
{"id":"q1","question":"Сколько голов внимания в базовой модели?","reference":"В базовой модели 8 голов внимания."}
```

`id` — уникальная непустая строка; `question` — непустая строка (пробелы по краям удаляются до сохранения манифеста); `reference` — необязательный эталонный ответ. Эталон не передаётся в RAG. Не генерируйте эталоны из проверяемого ответа: сформулируйте их по первоисточнику и проверьте вручную. Набор должен включать реальные вопросы пользователей, RU/EN, точные факты, составные вопросы и случаи отсутствия ответа.

Дополнительные поля набора: `language`, `category`, `difficulty`, `answerable`, `source_file`, `source_pages`, `source_sections`. Страницы нумеруются с 1 по исходному PDF; они не являются номерами источников в ответе. Для вопросов без ответа `reference` отсутствует, а `expected_behavior` описывает ожидаемый отказ. Эти поля не передаются генератору и сохраняются как метаданные. Описание версии PDF, SHA256 и особенности набора — в `data/questions.meta.json`.

В загруженной версии есть расхождение: abstract и таблица 2 дают **41.8 BLEU EN-FR**, текст раздела 6.1 — **41.0**. Вопрос `attn_29_translation_table` явно относится к таблице 2; `attn_30_french_discrepancy` проверяет обнаружение самого расхождения. Не следует считать любое из этих чисел безусловной ошибкой ответа без учёта вопроса и источника.

Отдельно вручную проверяйте 4 вопроса без ответа: random seed, RoPE, задержку на A100 и сравнение с BERT на GLUE. Для них три метрики с эталоном пропускаются; корректный отказ может получить низкую Answer Relevancy или undefined Faithfulness. Общая сводка сама не разделяет строки по `answerable`.

В конце ноутбука 02 выполните пакетный inference. Затем откройте 03 и укажите тот же `RUN_NAME`. В нём используются:

- Faithfulness: подтверждение утверждений ответа контекстом.
- Answer Relevancy: релевантность ответа вопросу; нужны judge и embeddings.
- Context Precision with Reference: полезность контекстов и порядок выдачи.
- Context Recall: покрытие фактов эталона контекстом.
- Factual Correctness: фактическая согласованность ответа и эталона, F1.

Последние три метрики требуют эталона. Контекстные метрики пропускаются при пустом контексте. Отказы от ответа проверяйте отдельно: уместный отказ может иметь низкую релевантность или неопределённую faithfulness. Для визуальных источников метрики оценивают текст OCR/VLM, а не качество распознавания исходных пикселей.

Ragas вызывает судью несколько раз на вопрос. Пересчёт может расходовать средства API; начните с малого набора. Универсальных порогов качества нет. Сравнивайте настройки на одном наборе и с одним судьёй, просматривая конкретные ошибки.

Документация: [Ragas collections](https://docs.ragas.io/en/stable/howtos/migrations/migrate_from_v03_to_v04/), [метрики](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/).

## Результаты и восстановление

```text
outputs/indexes/<INDEX_NAME>/
  index.json, binding.json       # параметры и привязка к коллекции
  docling/<doc_id>.json          # структурированный документ до чанкирования
  parsed/<doc_id>.json           # готовые чанки каждого документа
  indexed.jsonl                 # подтверждённые upsert
outputs/runs/<RUN_NAME>/
  run.json                      # конфигурация и полный план вопросов
  answers.jsonl                 # ответы + точный контекст промпта
  evaluations/<EVAL_NAME>/
    judge.json, scores.jsonl
    details.csv, summary.csv
```

Checkpoint пишется после завершения операции. Повторите ячейку прерванного шага: успешные элементы пропускаются, последние ошибки повторяются. Все долгие этапы, включая Ragas, останавливаются через Interrupt Kernel. Незавершённая последняя строка JSONL восстанавливается перед следующей записью. После удаления коллекции индексирование проверяет наличие точек и восстанавливает их. Один каталог должен иметь только одного писателя одновременно.

Для другого корпуса, embeddings, чанкинга, OCR/VLM или сервера Qdrant задайте новые `INDEX_NAME` **и** `COLLECTION`. Для другого промпта/настроек inference задайте новый `RUN_NAME`. Для другого судьи — новый `EVAL_NAME`. Проверка манифеста не позволяет незаметно смешать разные эксперименты. Если меняете реализацию алгоритма в ячейках или helpers, увеличьте соответствующий `implementation` и выберите новые имена эксперимента/индекса. Пул RRF-кандидатов остаётся одинаковым при включении/выключении reranker для сопоставимого сравнения; новый маршрут использует implementation=2 для индекса и implementation=3 для inference. Прежние классы сохраняют свои версии и доступны для совместимости.

В сводке `planned` показывает все вопросы; `ok`, `skipped`, `error`, `undefined`, `missing` раскрывают полноту. Среднее считается только по `ok`; пропуски не подменяются нулями. При повторном inference изменённый ответ инвалидирует прежние оценки. Последняя ошибка также отменяет более ранний успех.

## Проверки без моделей

Из этой папки после установки зависимостей:

```bash
python -m unittest discover -s tests -v
```

Проверки используют in-memory Qdrant и подставные ответы API, не вызывают реальные модели и не запускают Docker. Они выполняют ячейки трёх ноутбуков на подставных API, проверяют текстовый вывод, сохранение/возобновление, поиск и все пять метрик. Реальные inference, OCR/VLM и Ragas через ваш API запускаете вы.

## Что повторить после изменения

| Что изменили | Что выполнить снова | Новые имена |
|---|---|---|
| Вопрос | Настройки вопроса → поиск → ответ | Не нужны для одиночной пробы |
| `SEARCH` | В 02: поиск → ответ; для оценки — пакетный запуск | Новый `RUN_NAME` для нового эксперимента |
| Промпт | В 02: настройки ANSWER_PROMPT → просмотр промпта → ответ; затем пакетный запуск | Новый `RUN_NAME` |
| PDF, embeddings, OCR/VLM, чанкинг, Qdrant | 01 сверху вниз → 02 сверху вниз | Новые `INDEX_NAME`, `COLLECTION` и `RUN_NAME` |
| `.env` | Перезапуск kernel и ячейки сверху вниз | При смене моделей/сервисов — имена по строкам выше |
| Судья | Перезапуск kernel ноутбука 03 → настройки → загрузка → расчёт | Новый `EVAL_NAME` |
| Только фильтр отчёта | Просмотр таблицы и примера | Не нужны; вызовов судьи нет |

После перезапуска kernel выполняйте текущий ноутбук сверху вниз. Ноутбук 02 загружает готовый индекс с диска и Qdrant, без повторного разбора документа. В 01 документы и точки индекса восстанавливаются из checkpoints.

## Если что-то не получилось

| Симптом | Что проверить и сделать |
|---|---|
| `Connection refused` | Запущен ли сервер и совпадают ли адрес/порт с `.env`? |
| `/health` отвечает 503 | Дождаться окончания загрузки модели в терминале сервера |
| Модель не найдена | Сверить `*_MODEL` с `id` из `<BASE_URL>/models` и `--alias` |
| 401/403 | Проверить ключ и права доступа к выбранной модели. Оценка останавливается после первой такой ошибки, сохранив прогресс. Для того же провайдера можно оставить `JUDGE_API_KEY` пустым, чтобы использовать `LLM_API_KEY`; затем перезапустить kernel |
| В ноутбуке 03 нет запуска/ответов | Выполнить пакетную ячейку 02; проверить `RUN_NAME` и папку `outputs/runs/` |
| Конфигурация не совпадает с манифестом | Выбрать новые имена эксперимента/индекса по памятке выше |
| Выполнение прервано | Повторить прерванную ячейку; после перезапуска kernel сначала восстановить предыдущие этапы |
| После пробы много `missing` | Это ожидаемо при `LIMIT=3`; для полного расчёта поставить `None` |
